## Architecture Fit

### Hardware Block Diagram Mapping

The NTC1/R4 voltage-divider block occupies the lower-right region of the daughter board
schematic (Column B/C, y ≈ 264 mm in A2 portrait layout).  This entire sub-circuit is
removed and replaced in-place by a 3-pin DHT11 breakout connector that retains the same
GPIO routing through J8 pin 23:

```
Before:
  +3V3 ──► R4 (10kΩ) ──► [NTC_ADC net] ──► NTC1 ──► GND
                               │
                          J8 pin 23 ──► ESP32-P4 GPIO16 (ADC1)

After:
  +3V3 ──► J9 pin 3 (VCC)
           J9 pin 2 (DATA) ──► [DHT11_DATA net] ──► J8 pin 23 ──► ESP32-P4 GPIO16
           J9 pin 1 (GND)  ──► GND
               │ 3-pin Molex KK-254 cable
           DHT11 breakout (Reichelt 239086)
             VCC ◄── cable pin 3
             DATA ──► cable pin 2  (pull-up onboard breakout, see §2.2 note)
             GND ──► cable pin 1
```

The DS18B20 probe block (J6 / R14 / R15 / LED6) below the DHT11 row is untouched.

### Firmware Module Structure (P-FW-01)

Only the `temp` module and the `web` module are changed.  All other module boundaries
are preserved exactly:

| Module | Responsibility | Change |
|---|---|---|
| `fan` | LEDC PWM, tach ISR, RPM | **No change** |
| `temp` | Sensor read, temperature + humidity reporting | **Rewritten** — DHT11 replaces ADC+Steinhart-Hart |
| `probe` | 1-Wire DS18B20 bus scan and read | **No change** |
| `web` | Routes, JSON serialisation, LittleFS | **Extended** — add `humidity_pct` to status response |
| `config` | NVS, defaults, schema validation | **No change** |
| `ota` | OTA handler, prog LED | **No change** |
| `main` | Init order, task creation | **No change** — `temp_init()` call site unchanged |

### PCB Layout Changes

PCB changes are made exclusively via the KiCad GUI on
`hardware/kicad/PoE-FanController.kicad_pcb` (P-KI-07).  No script may write to or
regenerate this file.

#### Steps (KiCad GUI)

1. **Delete NTC1 footprint** — select the NTC1 THT axial resistor footprint
   (`Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal`) and delete it
   (including all copper pads and silk).

2. **Delete R4 footprint** — select the R4 THT axial resistor footprint
   (`Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P7.62mm_Horizontal`) and delete it.

3. **Add J9 footprint** — place
   `Connector_Molex:Molex_KK-254_AE-6410-03A_1x03_P2.54mm_Vertical` (ref: `J9`,
   value: `Molex_KK254_3pin`) in the vacated NTC1/R4 area (right zone, x > 21 mm, F.Cu
   only per P-HW-02).  J9 should be positioned on the right board edge for cable access
   (P-HW-03 spirit; J9 carries an external cable assembly).

4. **Net assignment** — assign pads: Pin 1 → `GND`, Pin 2 → `DHT11_DATA`, Pin 3 → `+3V3`.

5. **Route traces** — use 0.25 mm signal track (P-HW-07) for DHT11_DATA from J9 pin 2
   to J8 pin 23.  Route GND and +3V3 pads to their respective copper pours.

6. **Silkscreen** — add GND / DATA / +3V3 silkscreen labels beside J9 to guide correct
   cable crimping (Molex keying provides physical protection; labels aid assembly).

7. **DRC** — run DRC; confirm zero errors (P-TEST-03).

8. **Update GND pour** — refill copper pours after routing.

#### PCB layout notes

- **P-HW-09 applies to J9:** J9 receives an external cable assembly from the DHT11
  breakout module.  The Molex KK-254 housing (22-01-3037) satisfies P-HW-09; a generic
  pin header is not permitted.
- Courtyard for `Molex_KK-254_AE-6410-03A_1x03_P2.54mm_Vertical` is approximately
  4.25 × 6.80 mm — verify no overlap with DS18B20 section below or LED circuitry above.
- Old NTC1/R4 location (Column B/C, y ≈ 264 mm schematic) maps to the PCB area below
  the LED2/prog-LED circuitry in the right zone.  Confirm placement clears J6 courtyard.

#### `firmware/src/temp.cpp` — Complete Rewrite

The file is rewritten in full.  The public API surface stays backward-compatible:
`temp_init()` and `temp_read_celsius()` are retained with identical signatures;
`temp_read_humidity_pct()` is added.

Skeleton (library-agnostic; exact API depends on library confirmed by `esp32.expert`):

```cpp
/**
 * @file temp.cpp
 * @brief DHT11 temperature + humidity sensing for PoE FanController.
 *
 * Single-wire protocol on GPIO16 (DHT11_DATA_PIN, J8 pin 23).
 * Reads are performed by a FreeRTOS timer callback every DHT11_MIN_INTERVAL_MS.
 * temp_read_celsius() and temp_read_humidity_pct() return cached values; safe to
 * call from async web handler context (P-FW-04).
 */
#include <Arduino.h>
#include <DHT.h>            // Adafruit DHT sensor library (or library per esp32.expert)
#include "pins.h"

static DHT  _dht(DHT11_DATA_PIN, DHT11);
static float _temp_c    = 25.0f;   // last valid temperature (°C)
static float _hum_pct   = 50.0f;   // last valid humidity (%)
static int   _err_count = 0;
static const int MAX_ERRORS = 10;
static TimerHandle_t _timer = nullptr;

static void dht_read_task(TimerHandle_t /*xTimer*/)
{
    float t = _dht.readTemperature();
    float h = _dht.readHumidity();
    if (!isnan(t) && !isnan(h)) {
        _temp_c    = t;
        _hum_pct   = h;
        _err_count = 0;
    } else {
        if (++_err_count >= MAX_ERRORS) {
            _temp_c  = -999.0f;   // sentinel — sensor fault
            _hum_pct = -1.0f;
        }
        Serial.printf("[TEMP] DHT11 read error #%d\n", _err_count);
    }
}

void temp_init()
{
    _dht.begin();
    // FreeRTOS software timer: auto-reload, period = DHT11_MIN_INTERVAL_MS
    _timer = xTimerCreate("dht11", pdMS_TO_TICKS(DHT11_MIN_INTERVAL_MS),
                          pdTRUE, nullptr, dht_read_task);
    xTimerStart(_timer, 0);
    Serial.println("[TEMP] DHT11 initialised on GPIO" STRINGIFY(DHT11_DATA_PIN));
}

float temp_read_celsius()      { return _temp_c;  }
float temp_read_humidity_pct() { return _hum_pct; }
```

## Testing Strategy

### PlatformIO Native Unit Tests

The DHT11 single-wire protocol driver is hardware-dependent and cannot run on the native
platform (P-TEST-05 scope exclusion applies).

However, the following should be unit-tested natively:

| Test | Module | What to verify |
|---|---|---|
| Rename `NTC_ADC_PIN` → `DHT11_DATA_PIN` | `test_pins` | `#define DHT11_DATA_PIN 16` exists; `NTC_ADC_PIN` does not |
| Sentinel passthrough | `test_temp` | `temp_read_celsius()` returns –999.0f when fault counter ≥ MAX_ERRORS |
| Humidity sentinel passthrough | `test_temp` | `temp_read_humidity_pct()` returns –1.0f under same condition |
| JSON null mapping | `test_web` (mock) | `humidity_pct` serialises as JSON `null` when `hum < 0.0f` |

### Hardware Bring-up Checks

These must be completed on a physical board with DHT11 breakout installed:

1. **Power rail check** — Confirm +3.3 V on J_DHT11 pin 1 with multimeter.
2. **Pull-up check** — Confirm DATA line idles HIGH (≈3.3 V) with oscilloscope or multimeter
   (this verifies the breakout's onboard pull-up or PCB pull-up is present).
3. **Serial log check** — Observe `[TEMP] DHT11 initialised on GPIO16` at boot; no error
   messages within first 10 reads.
4. **REST API check** — `curl http://<board-ip>/api/v1/status` — confirm `temp_c` and
   `humidity_pct` fields present with plausible values (not null, not –999).
5. **Accuracy check** — Compare DHT11 temperature to calibrated reference thermometer;
   expect within ±3 °C (SC-07).
6. **Humidity accuracy check** — Compare DHT11 humidity to reference hygrometer; expect
   within ±8 % RH (SC-08).
7. **Fault injection** — Disconnect DHT11 breakout while board is running; confirm `humidity_pct`
   becomes `null` and `temp_c` becomes `null` after MAX_ERRORS consecutive failures.
