## Architecture Fit

The generator is a pure development-time tooling concern — it has no runtime presence in firmware or
web UI. It currently sits as a single file at `hardware/generate_project.py`. This plan turns it into
a Python package at `hardware/generator/`, preserving the external interface (`python3
generate_project.py`) and every file-path contract that CI and the §7A schematic-readability
standards depend on.

**Constitution references:**

| Principle | Relevance |
|---|---|
| P-HW-05 (lines 121–122) | Schematic generated by script; must never be hand-edited |
| P-KI-04 (lines 303–307) | Generator is `.kicad_sch` source of truth |
| P-KI-05 (line 309) | Project must be self-contained; no external library paths |
| P-DEV-04 (line 434) | Constitution amendment required before implementing change |
| P-DEV-06 (line 443) | PEP 8, 4-space indentation for Python |
| §7A preamble (line 320) | Schematic readability rules apply to the generator script |
| §2.1 table row (line 35) | Schematic source of truth = generator script |

Phase 0 (constitution amendment) is an explicit prerequisite enforced by P-DEV-04.

```
hardware/
├── generate_project.py          # thin entry point: ≤ 30 lines; imports generator; calls run()

### Import dependency graph (must remain acyclic)

```
generate_project.py
  └── generator/__init__.py
        ├── generator/components.py  ──→  generator/schematic.py  ──→  generator/utils.py
        │                            ──→  generator/pcb_utils.py  ──→  generator/utils.py

`schematic.py` imports only `utils.py`. `pcb_utils.py` imports only `utils.py`. `components.py`
imports `schematic.py` and `pcb_utils.py`. `bom.py` imports only `utils.py` (for `OUT_DIR`).
No cycles.

## PCB Source-of-Truth Transition

| Dimension | Before | After |
|---|---|---|
| `write_pcb()` existence | Present (lines 951–1149) | Deleted — function does not exist |
| `.kicad_pcb` lifecycle | Build artefact — overwritten on every run | Committed source of truth — never regenerated |
| Manual routing | Lost on every generator run | Survives indefinitely |
| PCB change workflow | Edit Python → regenerate | Open KiCad GUI → edit → save → commit |
| CI DRC input | PCB regenerated by script then checked | DRC runs directly on committed `.kicad_pcb` |

## CI Changes (`hardware-check.yml`)

### `validate-generator` job (syntax check)

**Before:**
```yaml
- name: Syntax check generator
  run: python -m py_compile hardware/generate_project.py && echo "Syntax OK"
```

**After:**
```yaml
- name: Syntax check generator
  run: |
    python -m py_compile hardware/generate_project.py && echo "Entry point OK"
    for f in hardware/generator/*.py; do
      python -m py_compile "$f" && echo "  OK: $f"
    done
    echo "All modules syntax OK"
```

This satisfies FR-09 / AC-8.

### `kicad-erc-drc` job (generator step + guard)

**Before:**
```yaml
- name: Run PCB generator
  run: |
    cd hardware
    KICAD_FP_BASE=/usr/share/kicad/footprints python3 generate_project.py
```

**After:**
```yaml
- name: Regenerate schematic
  run: |
    cd hardware
    KICAD_FP_BASE=/usr/share/kicad/footprints python3 generate_project.py

- name: Verify PCB file not modified by generator
  run: git diff --exit-code hardware/kicad/PoE-FanController.kicad_pcb
```

The guard step (`git diff --exit-code`) will fail the CI job with a non-zero exit code if the
generator ever writes to `.kicad_pcb` — a regression safety net that satisfies FR-08 / AC-5 / AC-7.

> **No other steps in `kicad-erc-drc` require modification.** ERC, DRC, and artifact upload steps
> run on the same files as before; only the generator's scope has narrowed.

### Phase 2 — Thin Entry Point + Delete `write_pcb()`

**Files modified:** `hardware/generate_project.py`

Replace the entire content of `generate_project.py` with the thin wrapper:

```python
"""
hardware/generate_project.py — entry point for the PoE FanController generator.

Delegates all work to the hardware/generator/ package.
Usage:
    cd hardware
    KICAD_FP_BASE=/usr/share/kicad/footprints python3 generate_project.py
"""
import os
from generator import build_schematic, write_bom
from generator.utils import OUT_DIR, PROJ, write_pro

if __name__ == "__main__":
    os.makedirs(OUT_DIR, exist_ok=True)

    print("Project file...")
    write_pro()

    print("Building schematic...")
    sch = build_schematic()
    sp = os.path.join(OUT_DIR, f"{PROJ}.kicad_sch")
    with open(sp, "w", encoding="utf-8") as f:
        f.write(sch.render())
    print(f"  wrote {sp}")

    print("BOM...")
    write_bom()

    print("\nDone.")
```

> The `write_pcb()` call is removed. No `.kicad_pcb` is written.
> The "Run ERC with:" developer hint block is also removed (it references a Windows-only path that
> is irrelevant in CI; if desired it can be moved to `README.md` or `DESIGN.md`).

**Files deleted:** None (old functions are simply not present in the new file; `write_pcb` is gone).

## Testing Strategy

### Unit / syntax tests

- `python -m py_compile` on all six package modules and the entry point (Phase 3 CI change).
- `python3 -c "from generator import build_schematic, write_bom"` import smoke test (Phase 2
  local check; can be added as an explicit CI step if desired).

### Functional regression tests

- **ERC gate (AC-3):** `kicad-cli sch erc` on the regenerated `.kicad_sch` — zero errors required.
  This is an existing CI gate and constitutes the primary functional regression test.
- **BOM content (SC-10):** `diff` the `bom.csv` output against the pre-refactor baseline.
  Recommend capturing a baseline artifact from the last pre-refactor CI run before merging.

### PCB non-modification test

- **AC-5 / SC-05:** `git diff --exit-code hardware/kicad/PoE-FanController.kicad_pcb` as a CI step
  (Phase 3). Fails loudly if any byte of the PCB file changes.

### Manual integration check

1. Run `python3 generate_project.py` locally (Windows, with `KICAD_FP_BASE` set).
2. Open `hardware/kicad/PoE-FanController.kicad_sch` in KiCad 10 and confirm all components and
   wiring render correctly.
3. Confirm `hardware/kicad/PoE-FanController.kicad_pcb` is unmodified (Git status shows no diff).
